Avoiding Stack Overkill

When I redid this homepage for the 4th time I was initially going to make it super fancy like I had done in the past. I had made this in Neocities in plain HTML and CSS with complete custom styling. It was super easy to do. Then I remade it in Vue to get my hands on the sweet sweet components. Then I remade it in React more out of need to showcase that I can do it than necessity, adding fancy stuff like back-to-top navigation and automatic light/dark theme switching.

But course there are downsides to everything. Hosting this on Neocities or GitHub pages necessiated the dreaded hashtag routes. Then there is the added complexity of build process and maintaining dependencies (oh boy isn't the sheer size of node_modules ever a sight to behold), and the sad fact that despite working on shadow DOM and loading only partial components, the performance just wasn't as snappy as it was on the original simple Geocities page. So, I decided to get back to simpler times with the added wisdom accumulated over professional career. I wanted real hard links and snappiness back.

# Getting to it

After briefly looking at Jekyll and deciding "I don't want to waste time with that", I started by ripping all the React jsx apart into basic HTML, then tidying them into as simple structure as possible and made it semantic. Not many divs around this neighborhood. Next I identified spots of mass repetition, places where if I were to change anything I'd have to change most if not all the other pages to accomodate for that change. List of blog entries housed as an aside on every post and the header were the obvious ones. Those I made into much overlooked web components, postfixed my components in HTML with "frag" as a homage to Thymeleaf naming convention of calling reusable components fragments. Problem solved.

Finally, because I had already made the HTML semantic, I chose PicoCSS to take care of my styling needs to create the cookie-cutter modern look, complete with dark/light theme preference sensing and responsiveness across device sizes. As long as the HTML is semantic, it automagically styles the entire application without any extra class or id tags. Of course, I ended up overridig so much that I scrapped it and did all-custom styling. But if time is tight and site is simple, PicoCSS gets the job done.

# Conclusion

You don't need much to create a modern looking, readily SEO'd, highly accessible, easily maintainable website with reusable components. What matters most is the end-user experience and doing stack overkills contributes nothing to that.
